Sensei Language Preference Cookie

本文档说明 Sensei 如何在同一浏览器中长期记录最后明确生效的语言，以及 Dashboard 和未来页面应该如何安全消费这项状态。

当前交付边界：Sensei 已作为 Cookie 生产端实现该契约； Dashboard、Auth 和其他消费端尚未改造，应按照本文档单独接入。

1. Cookie 契约

名称 Sensei_locale
值 Sensei 已发布语言集合中的规范小写值，例如 en、 fr、ja 或 zh-hant。
Path /，同一主机下的所有路径均可读取。
有效期 Max-Age=31536000（一年），每次有效写入时刷新。
SameSite Lax
Secure HTTPS 环境设置；本地 HTTP 开发环境不设置。
Domain 不设置，因此是 host-only Cookie。它不会自动共享给其他子域名；消费端必须 运行在能够接收该 Cookie 的同一主机上。
HttpOnly 不设置，因为浏览器端消费页面需要读取它。
安全含义 仅用于显示语言偏好。它是用户可修改的输入，绝不能用于登录、授权或权限判断。

当前 Sensei 已发布值

en、ja、es、it、 ar、pt、zh-hant、 pl、ko、fr。 Sensei 的权威来源仍然是根目录 i18n.config.json 中的 publishedLocales；消费端应维护并验证自己真正支持的子集。

2. Sensei 如何记录语言

  1. 用户进入带有受支持语言前缀的页面，例如 /fr/ 或 /zh-hant/pricing/，公共布局记录该明确语言。
  2. 用户通过语言切换器进入真实存在的目标页面时，在导航前记录目标语言。
  3. 目标语言页面不存在、切换器回退到英文页面时，在回退导航前记录实际生效的 en。

不会自动覆盖 Cookie 的情况

  • 无语言前缀的路径不会仅凭页面加载写入 en。这类路径可能是英文内容， 也可能是与语言无关的流程页面。
  • 因此用户从 /fr/ 进入 /dashboard/ 或其他无前缀页面时， 原有 fr 偏好会被保留。
  • Cookie 无法访问或写入时，页面和语言导航继续执行，不因偏好记录失败而中断。

语言解析优先级

  1. 当前 URL 中明确、受支持的语言前缀；
  2. 经过消费端白名单验证的 Sensei_locale；
  3. 消费端配置的默认语言，当前 Sensei 默认值是 en。

Cookie 表示“最后明确生效的语言”，不是“最后尝试点击的语言”。非法值、大小写错误值、 不支持的值和无法解码的值都必须忽略。

3. 未来消费端如何接入

浏览器端消费页面建议遵循以下顺序：

  1. 从 document.cookie 中只查找 Sensei_locale；
  2. 安全解码，并用消费端自己的受支持语言集合验证；
  3. 缺失、非法或解码失败时使用 en；
  4. 只有在验证完成后，才把语言值映射或编码到 URL；
  5. 若消费端未来有自己的显式语言 URL，显式 URL 的优先级高于 Cookie。

浏览器端参考实现

const COOKIE_NAME = "Sensei_locale";
const SUPPORTED_LOCALES = new Set(["en", "fr", "ja", "zh-hant"]);

function readPreferredLocale(cookie = document.cookie) {
  const entry = cookie.split(";").map((part) => part.trim())
    .find((part) => part.startsWith(`${COOKIE_NAME}=`));
  if (!entry) return "en";
  try {
    const value = decodeURIComponent(entry.slice(COOKIE_NAME.length + 1));
    return SUPPORTED_LOCALES.has(value) ? value : "en";
  } catch {
    return "en";
  }
}

function buildMainSiteUrl(path, locale = readPreferredLocale()) {
  const normalizedPath = path.startsWith("/") ? path : `/${path}`;
  const prefix = locale === "en" ? "" : `/${encodeURIComponent(locale)}`;
  return `https://www.senseiai.me${prefix}${normalizedPath}`;
}

调用示例

buildMainSiteUrl("/");
// en      -> https://www.senseiai.me/
// fr      -> https://www.senseiai.me/fr/
// zh-hant -> https://www.senseiai.me/zh-hant/

buildMainSiteUrl("/pricing/");
// en      -> https://www.senseiai.me/pricing/
// fr      -> https://www.senseiai.me/fr/pricing/
// zh-hant -> https://www.senseiai.me/zh-hant/pricing/

消费端集成注意事项

  • 不要把 Cookie 值直接拼接进 URL，也不要接受 zh-Hant 等非规范大小写。
  • 消费端的语言集合可以小于 Sensei 的发布集合；不支持的值必须回退到 en，不能猜测转换。
  • 服务端渲染页面可从请求的 Cookie 请求头读取同名值，但仍要执行相同的 解码和白名单验证。
  • 若未来 Dashboard 自己拥有多语言 URL，先解析 Dashboard 的明确 URL 语言，再读取 Cookie；不要反过来用 Cookie 覆盖用户正在访问的明确 URL。
  • 该契约不规定未来 Dashboard 必须采用 /fr/dashboard/、无前缀翻译页面， 或其他路由形式。路由方案由消费端决定。

4. Dashboard 当前已知问题 尚未解决

以下内容是当前 Auth 仓库 Dashboard 实现的记录，不属于本次代码修改范围：

  • Dashboard 由 Auth 仓库提供，公开路径是 /dashboard/；该 pathname 本身不包含主站语言前缀。
  • public/dashboard/sidebar.js 的 getCurrentLocalePrefix() 仍然尝试从 Dashboard pathname 推导语言， 在 /dashboard/ 下会回到英文。
  • Dashboard 的硬编码语言列表使用 zh-Hant，而 Sensei 的规范值是 zh-hant。Cookie 校验区分大小写，因此二者不能视为同一个合法值。
  • Home、Pricing、Downloads、Logo、套餐入口，以及没有支付平台信息时的订阅管理入口， 仍包含固定英文目标地址。
  • Dashboard 目前还没有读取或验证 Sensei_locale。

Dashboard 后续接入时应删除“从 /dashboard/ pathname 猜主站语言”的依赖， 改用本文档的优先级和白名单规则；但本次没有修改上述任何文件。

5. Checkout continuation 已知问题 尚未解决

/checkout/continue/ 是无语言前缀的流程页面，因此加载它不会覆盖已有的 Sensei_locale。但当待处理支付流程缺少可用的返回地址时，当前实现仍固定回退到 /pricing/。这个回退地址没有使用已保存的语言，可能使用户回到英文 Pricing。

本次只记录该问题，不修改 /checkout/continue/。未来处理时，应先验证 Cookie， 再用消费端支持的语言构造本地化 Pricing 回退地址。

6. 本次明确不解决的事项

  • 不修改 Auth、Dashboard 或 Billing。
  • 不修复 Dashboard 中固定的 Home、Pricing、Downloads、Logo 或套餐链接。
  • 不统一 Dashboard 的语言列表，也不修复 zh-Hant 大小写问题。
  • 不为 Dashboard 增加多语言页面或决定其未来路由结构。
  • 不修改 /checkout/continue/ 的固定 Pricing 回退。
  • 不把语言保存进用户账户，也不跨浏览器或设备同步。
  • 不增加边缘自动跳转、数据库状态、权限判断或部署步骤。
